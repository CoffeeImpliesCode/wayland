- Acceptance: a v3 client receives wl_data_offer.source_actions immediately after the offer's mime events on every offer delivery; v1/v2 offers get no event (version guard); the payload reflects src.actions. - Risk: all three references send source_actions only on DRAG offers (wlroots wlr_drag.c:99-101; smithay data_device/mod.rs:478-479; KWin datadevice.cpp:282 — note the finding's "dataoffer.cpp:214" is drifted; the actual sendSourceActions is dataoffer.cpp:129-149, call site datadevice.cpp:282). If strict reference parity is preferred, scope the emission to the F-SEL-1 drag path instead — but then the fix is untestable until DnD lands, losing the disposition's standalone intent.
