### S6 cursor hotspot ignores buffer scale [INFO] → FIX (Phase 2)
- Files: src/compositor/cursor.zig — client-cursor placement `node.x = x - seat.cursor_hotspot_x` / `node.y = y - seat.cursor_hotspot_y` (:213-214), texture drawn at BUFFER size `dst_width = tex.width` / `dst_height = tex.height` (:211-212), draw path world position (:254-255 `seat.pointer_x - seat.cursor_hotspot_x`). The cursor surface's buffer scale is available as `surface.current.scale` (surface.zig:152). Reference: KWin divides the hotspot by serverScale·clientToCompositorScale (pointer.cpp:90); the protocol defines the hotspot in surface-local (logical) coordinates.
- Change: when the client cursor surface's buffer scale > 1, render the texture at surface size — `dst_width = tex.width / scale`, `dst_height = tex.height / scale` (integer; guard `scale > 0` and non-zero result) — so the image occupies its logical footprint, and keep the hotspot unscaled (it is already in logical coordinates, matching the logical-size image). Same effective result as KWin's division with the buffer-size rendering. In `update()` (:211-214) compute the scale from the resolved surface (`s.current.scale`); in `draw()` (:254-255) the seat does not carry the scale — either store the applied scale on the Cursor when update() runs (a `client_scale: i32 = 1` field set in update, read in draw) or recompute from `seat.cursorSurface()`.
- Test: cursor.zig wire test (TestCursorServer pattern, :420-549) — client sets a cursor surface with `wl_surface.set_buffer_scale(2)`, sets a 32x32 buffer, set_cursor with hotspot (5,6); run `update()`; assert buf_node.x == pointer_x - 5, dst_width == 16, and (after a draw) the rendered world size is 16x16.
- Acceptance: a scaled cursor surface renders at its logical size with the hotspot landing exactly on the pointer; unchanged behavior for scale-1 surfaces (the only case reachable today — the effect is nil until scaled outputs/clients appear, but the contract gap closes).
- Risk: low — scale-1 is the identity path; only the >1 branch changes. Integer division must not produce a 0-sized node for a small buffer (clamp to 1). No output-scale plumbing exists yet; when fractional scale lands, extend the same divisor chain (this is why it sits in Phase 2).

- Change: the re-arm at :1983 must target the seat's actual deadline, not a fixed interval, so a marginally-early tick does not skip the emission AND advance the deadline by a full interval (first repeat lands at delay+interval instead of delay+rate). - Risk: low — onRepeatTick's deadline advance on emit stays unchanged; the change is confined to the re-arm duration. `@max(1, ...)` keeps zio timers from 0-duration spins. Check that the seat's nowMs and main.zig's clock use the same monotonic source (both monotonic-ms; assert in the test).
