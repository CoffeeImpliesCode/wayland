### C1 Parent-destroyed wl_subsurface is destroyed instead of made inert [MAJOR] → FIX (Phase 1)
- Files: src/compositor/subsurface.zig — `onParentDestroy` (line 403), `teardownOnSurfaceDeath` (line 502), `subsurfaceRequest` (line ~336), `subsurfaceDestroy` (line 516), `Subsurface` struct (line 48).
- Change: On parent destroy, keep the wl_subsurface RESOURCE alive and inert instead of destroying it (the current `teardownOnSurfaceDeath` at 502 calls `ss.resource.destroy()` — a later client destroy/request on the dead id is an invalid_object protocol error and disconnects a legal-order client; spec wayland.xml:3288-3289 only says "the sub-surface is unmapped").
  1. Add `inert: bool = false` to `Subsurface`.
  2. `onParentDestroy`: keep `flushCached` (line 405) + `unmapChild` (line 406), then replace `teardownOnSurfaceDeath(ss)` with an inert step: `detachListeners(ss)`; remove the entry from `sc.subsurfaces` (same `indexOfScalar`+`orderedRemove` as `subsurfaceDestroy`); clear the child role (`ss.surface.role = null; ss.surface.role_resource = null` — the child keeps rendering as a plain surface, matching today's `subsurfaceDestroy` behavior); set `ss.inert = true`. Do NOT destroy the resource.
  3. `subsurfaceRequest`: first line — `if (ss.inert) { if (request == .destroy) ss_res.destroy(); return; }` — every request on an inert wl_subsurface is silently ignored (wlroots: `subsurface_from_resource` returns NULL and each handler early-returns, wlr_subcompositor.c:43,56-61); destroy still destroys the resource.
  4. `subsurfaceDestroy`: guard the `ss.surface` role-clear with `if (!ss.inert)` — for an inert subsurface the child Surface may already be freed, so dereferencing `ss.surface` is UAF. Registry removal + free stay (removal is a defensive no-op; the entry was already removed at inert).
  5. Fix the `onParentDestroy` doc comment (line ~396-402), which currently misstates wlroots as "destroy-on-parent-destroy"; wlroots keeps the resource inert (`wl_resource_set_user_data(resource, NULL)`, wlr_subcompositor.c:43; file header line 4: "wl_subsurface becomes inert on parent surface destroy"). wlroots ref: subsurface_handle_parent_destroy wlr_subcompositor.c:253-258 → subsurface_destroy :35-44; smithay keeps the WlSubsurface object with a weak parent link (handlers.rs:555-620); KWin deletes only on child-surface destroy.
- Test: wire test in subsurface.zig — "parent destroy inerts the wl_subsurface; requests are ignored and destroy still works": SubsurfaceTest; child attach+commit (sync, deferred); parent attach+commit a buffer (flush → child maps); destroy the parent resource; assert registry len 0, `child.role == null`, `!child.mapped`; then call `subsurfaceRequest(ss_res, .set_position, ss)` and `.set_sync` on the inert resource → no crash, no state change, no protocol error; finally `subsurfaceRequest(ss_res, .destroy, ss)` → no crash; teardown (client destroy at deinit) does not double-free. Extend the existing "parent surface destroy removes the subsurface and clears the role" test to assert the resource survived (the request-ignore/destroy assertions above).
- Acceptance: a client that destroys its parent wl_surface and then destroys (or sends any request to) its wl_subsurface is never disconnected; requests on the inert object are ignored; `wl_subsurface.destroy` succeeds; the child surface stays unmapped (wayland.xml:3288-3289).
- Risk: the subtle bit is the `subsurfaceDestroy` inert guard (skipping the `ss.surface` deref) — get this wrong and an inert subsurface whose child later dies is a UAF. The inert `Subsurface` holds `ss.surface`/`ss.parent` pointers that dangle after either surface dies — they must never be dereferenced post-inert (listeners detached, requests no-op, registry entry removed → `surface_node.subsurfaceParent` and the per-frame `syncSubsurfaceNodes` never see it). `detachListeners` is idempotent so the double call is safe. Interplay with C2: clearing the role at inert also clears the `mapped_gate`, so a post-parent-death child commits as a plain surface (no dangling-parent gate walk).

### C2 Subsurface mapped state not coupled to the parent chain [MAJOR] → FIX (Phase 1)
- Files: src/compositor/role.zig (`SurfaceRole`, line 24), src/compositor/surface.zig (`applyCommit` step 10, lines 612-630), src/compositor/subsurface.zig (`subsurface_role` line ~133, `getSubsurface` listener setup line ~280, `detachListeners` line 509, `Subsurface` struct line 48), src/scene/surface_node.zig (`appendPresented` line 253, `updateOutputs` ~line 326, `trackSurface` line 375, struct fields line ~105).
- Change: make a subsurface's mapped/enter/present state derive from the parent chain (spec wayland.xml:3254-3258: "A sub-surface becomes mapped, when a non-NULL wl_buffer is applied and the parent surface is mapped... A sub-surface is hidden if the parent becomes hidden... These rules apply recursively"). Today step 10 maps on buffer+size alone and nothing propagates parent map/unmap — a hidden child still gets map/enter signals and lands in the presented list (frame_done + wp_presentation presented), surface.zig:612-630, scene collectPresented → main.zig:1494/1510.
  1. role.zig: add a map condition hook to `SurfaceRole`: `mapped_gate: ?*const fn (surface: *Surface) bool = null` (null = no gate; pattern matches the existing role hooks).
  2. surface.zig: add `pub fn isEffectivelyMapped(s: *Surface) bool` — positive-size current buffer AND (role.mapped_gate is null or passes); factor step 10 into `pub fn updateMapped(s: *Surface) void` (now_mapped = `s.isEffectivelyMapped()`; the transition — map: role.map + map signal; unmap: unmap signal first then role.unmap, F37 — unchanged, lines 619-630); `applyCommit` step 10 calls `s.updateMapped()`.
  3. subsurface.zig: `subsurface_role = .{ .name = "subsurface", .mapped_gate = subsurfaceMappedGate }`; the gate walks the subsurface parent chain and fails on the first unmapped ancestor — each ancestor's `mapped` flag is itself effective (gated at its own map), so a per-level check is the recursive rule: `fn subsurfaceMappedGate(s: *Surface) bool { var ss = subsurfaceFromSurface(s) orelse return true; while (true) { if (!ss.parent.mapped) return false; ss = subsurfaceFromSurface(ss.parent) orelse return true; } }`. Add `parent_map_listener` + `parent_unmap_listener` to `Subsurface`, subscribed to `parent.events.map`/`unmap` in `getSubsurface`, both firing `ss.surface.updateMapped()` (parent maps → gate passes → child maps → child's own map signal cascades to grandchildren; parent unmaps → gate fails → child unmaps → cascade); detach both in `detachListeners`.
  4. surface_node.zig: `appendPresented` (line 253): skip when `!sn.surface.mapped` (hidden children get no frame_done/presentation feedback); `updateOutputs` (~326): when `!sn.surface.isEffectivelyMapped()` → `setLeft()` instead of computing an intersection (no enter while hidden); add a `map_listener` (Surface.events.map → updateOutputs) so a child that maps via parent-chain propagation (no commit of its own) gets its enter tracking computed — its scene node already exists (created buffer-driven in `update()`), so the later per-frame sync (main.zig syncSubsurfaceNodes) can enable it. Rendering masking (ensureTree placeholder, line 305) is already correct and unchanged.
- Test: wire tests in subsurface.zig (these FAIL pre-fix): "desync child does not map while the parent is unmapped" — set_desync, attach+commit child → assert `!child.mapped`; "child maps when the parent maps" — continue: parent attach+commit a buffer → assert `child.mapped` (propagation via parent map signal); "child unmaps when the parent unmaps" — with parent+child mapped, parent commits a NULL buffer → assert `!child.mapped` (recursive unmap); "grandchild hidden when the ancestor unmaps" — nested subsurface (getSubsurface under the child), map all, unmap the root → assert the grandchild unmapped. surface_node test: "hidden subsurface is not presented" — child with a committed buffer under an unmapped parent → `collectPresented` excludes it; after the parent maps → included. UPDATE the three existing tests that encode the old behavior (parent commits without a buffer then asserts the child mapped): "synced child commits are deferred until the parent commits", "a desync child commits immediately", "wl_subsurface.destroy unmaps the child (F6)" — give the parent a buffer attach+commit first so it is mapped, preserving each test's intent.
- Acceptance: a subsurface never reports mapped/enter/present/frame_done while its parent chain is unmapped; it maps and is presented only when the whole chain is mapped; parent unmap propagates recursively down the tree; wl_surface.enter/leave track effective visibility (spec wayland.xml:3254-3258).
- Risk: sync-flush ordering — a child flushed during the parent's commit sees the parent's PRE-commit mapped (old value), so it must not map there; the new parent-map listener re-runs the child's transition right after the parent's own step 10, closing the wlroots-style one-frame gap (wlroots has the same ordering wrinkle; consider_map only helps at map time, wlr_subcompositor.c:195-199). The `mapped_gate` is a new hook; all other roles keep a null gate and are unaffected. updateOutputs gating relies on the new map listener for propagation-entered children — omit the listener and enter would be missed (client may throttle rendering). Existing tests that drive a subsurface map without a mapped parent must be updated (listed above); xdg-shell/shell tests that use subsurfaces should be spot-checked for the same pattern.

### C3 Rejected-commit signal ordering [MINOR] → ACCEPT — Reason: deliberate divergence, and a documented one — our early return on validation failure (surface.zig:497-498) skips role.client_commit and the client_commit signal for the rejected commit, which is cleaner than wlroots' ordering (surface_handle_commit runs role->client_commit and emits client_commit, then checks pending_rejected, wlr_compositor.c:580-592 — for a rejected sync-child commit it locks the cache that is never created, i.e. a latent wlroots bug); behavior for every accepted commit is identical. Add one sentence to the commit() doc comment (surface.zig:495-499) stating the intentional drop, so the subcompositor's cache-lock accounting (subsurface.zig onSurfaceClientCommit) is understood to never see a rejected commit.
