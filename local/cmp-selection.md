### 3. Adversarial correctness findings

F-SEL-1 (CRITICAL, DnD-blocking breadth) — No drag-and-drop state machine. start_drag (data_device.zig:356-377) only finalizes the source, validates the serial, and sends cancelled. wlroots implements the full machine (wlr_drag.c:30-380 grabs + focus, :213-231 drop, :402-442 icon role, :444-561 create); smithay (data_device/mod.rs:148-347); KWin (datadevice.cpp:69-142, updateDragTarget :238-301). Missing: wl_data_device.enter/motion/leave/drop, wl_data_source.dnd_drop_performed/dnd_finished/action, drag icon role, pointer/touch/keyboard grabs, drag offers, dropped-flag offer retention, finish-validation (accepted+action). Why: every drag-capable client (GTK, Qt, foot) fails to drag. [Known/deferred in notes/134 DD-1; restated as the dominant breadth gap, not fixed.]

F-SEL-2 (MAJOR, latent) — wl_data_offer.source_actions v3 event is never emitted. updateAction (data_device.zig:675-686) sends only wl_data_source.action + wl_data_offer.action; no code path sends source_actions anywhere in src/. The protocol mandates it "immediately after creating the wl_data_offer object" (protocols/wayland/wayland.xml:710-719), wlroots sends it on drag-offer creation (wlr_drag.c:99-101), KWin via sendSourceActions (dataoffer.cpp:214, called datadevice.cpp:279). The notes/134 DD-2 "FIXED" label covers only the `action` events; source_actions remains unemitted. Why: the destination never learns the source's offered actions — the ask menu and set_actions negotiation (which the XML references source_actions) have no input. No wire break today only because no drag offer exists (F-SEL-1). [Missing from prior audit — DD-2 marked the action path fixed without source_actions.]

F-SEL-3 (MINOR, selection-clear semantics, both modules) — A cancelled source stays wire-live and reusable; wlroots inerts it. On a replaced/cleared selection ours sends cancelled but keeps the source struct + live wire handler (data_device.zig:405-430 sourceDestroy runs only on resource destroy; same primary_selection.zig:312-335). wlroots destroys the source on cancel and nulls its resource user_data, inverting it (wlr_data_device.c client_data_source_destroy; wlr_primary_selection_v1.c:110-121). Consequence: a misbehaving client re-passing a cancelled source to set_selection — ours finalizes and SETS it as the new selection; wlroots parses the inert resource as NULL and CLEARS the selection (device_handle_set_selection passes source=NULL). Adversarial divergence in exactly the "selection clear semantics" axis. Also the cancelled source still accepts set_actions/offer in ours vs no-op in wlroots. Severity minor (requires a client re-using a cancelled source), but a real lifecycle divergence the 134 audit did not flag.

F-SEL-4 (MINOR) — set_selection with the SAME already-selected source re-delivers; wlroots silently updates the serial. Ours: after the KWin/gates pass, if the new source == current, we skip the cancel but still call deliverSelectionToFocus (data_device.zig:436-465), destroying old offers and sending a fresh data_offer + selection to the focused client. wlroots wlr_seat_set_selection early-returns on `selection_source == source`, updating only selection_serial, no re-send (wlr_data_device.c:184-189). Wire-visible divergence: an extra offer/selection round-trip on a re-set. Minor (re-set of the same source is unusual; both accept it).

F-SEL-5 (MINOR, latent single-seat) — get_data_device / get_device ignore the seat argument and never validate it is a live seat. data_device.zig:317-335, primary_selection.zig:250-... create a fully live device for any seat resource. wlroots creates an INERT device (no user data, unlinked) when the seat_client is NULL (wlr_data_device.c:226-252), so requests on a bogus/foreign seat's device are no-ops there, live here. Unreachable in the single-seat compositor unless a client binds a fabricated seat; parallels the XA-5 inert-seat handling that WAS fixed for xdg_activation. Minor.

F-SEL-6 (MINOR) — Primary selection offer.receive does not validate the requested mime type. primary_selection.zig:538-552 relays any mime (closes fd only when the source is gone). smithay validates for ALL offers including primary (offer.rs:177-182). This is inconsistent with the deliberate DD-7 hardening applied to wl_data_offer.receive (data_device.zig:704-768), which rejects unoffered mimes. wlroots also relays blindly (wlr_primary_selection_v1.c client_source_send), so this is a smithay-parity + internal-consistency gap, not a wlroots divergence. Minor.

F-SEL-7 (MINOR, latent) — in_ask action suppression not modeled. updateAction (data_device.zig:675-686, comment at :672-674) never suppresses the source/offer action events during "ask" negotiation, and there is no in_ask state; wlroots suppresses them (wlr_data_offer.c data_offer_update_action checks offer->in_ask, declared but never set in 0.20.2). Latent until F-SEL-1 lands; no wire impact today. Minor.

F-SEL-8 (MINOR, deliberate) — offer.set_actions invalid_action on a source-less offer is unreachable because dead offers are inerted (deadOfferHandler data_device.zig:814-822); the `offer.source orelse` branch (data_device.zig:806) is a defensive unreachable. Not a divergence (wlroots also inerts), noted for completeness.

### 4. Verdict
- Breadth: clipboard/primary-selection surface is complete and wire-conformant (all requests/events implemented, correct version gating, offer ordering, bind-time delivery, used-once, serial + superseded guards). The single structural breadth gap is drag-and-drop (F-SEL-1) — every DnD request/event (enter/leave/motion/drop, dnd_drop_performed/finished, drag icon, grabs) plus the source_actions event (F-SEL-2) wait on it.
- Correctness: the FIXED items in notes/134 (DD-3..DD-7, PS-1..PS-3) are genuinely resolved in the current code and match references. NEW adversarial divergences are F-SEL-2 (unemitted source_actions, mislabeled fixed), F-SEL-3 (cancelled-source reuse vs inert), F-SEL-4 (same-source re-delivery), F-SEL-6 (primary mime validation inconsistency). None of these are today-wire-breaking in the no-DnD state; F-SEL-2 becomes client-visible the moment DnD lands. Recommendation: wire source_actions into the drag-offer creation path (alongside updateAction) when F-SEL-1 ships, inert cancelled sources, and extend the DD-7 mime check to primary selection.
