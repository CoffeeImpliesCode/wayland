# VM Harness — Sanity Audit

Scope: `scripts/vm.nix` (107 lines), `scripts/vm-e2e.sh` (58), `scripts/vm-drm-e2e.sh` (121), `scripts/uinput-devices.py` (137). Reference sources: none external (house-built harness); qemu-vm.nix conventions read from the nixpkgs store (`/nix/store/3433bfqxndk785r5619pir0x7h0xqdh6-devenv-nixpkgs-patched/nixos/modules/virtualisation/qemu-vm.nix`) where guest filesystem behavior matters. Supporting source read to verify grep targets: `src/server/main.zig`, `src/server/client.zig`, `src/backend/drm.zig`, `src/backend/libinput.zig`, `src/utils/log.zig`, `build.zig`. Comparison: N/A — no wlroots/smithay counterpart for a test harness.

## Surface

`scripts/vm.nix` — NixOS VM definition:
- `boot.kernelParams` = `console=ttyS0`, `drm.debug=0xf` (vm.nix:20); grub on /dev/vda (21); `virtualisation.graphics = false` (22).
- qemu devices: `virtio-gpu-pci,xres=1280,yres=720`, `virtio-keyboard-pci`, `virtio-mouse-pci`, `-no-reboot` (vm.nix:27-32).
- `memorySize = 2048`, `diskSize = 4096` (33-34); 9p share `repo` → `/shared/repo` (35-40).
- systemPackages: zig, pkg-config, wayland(+dev), wayland-protocols, libxkbcommon(+dev), libdrm(+dev), libinput(+dev), libevdev (45-60); system-wide `PKG_CONFIG_PATH` env (61-62).
- `compositor-demo-drm` service: boot default (`wantedBy multi-user.target`), oneshot, ExecStart bash vm-drm-e2e.sh, journal+console, per-service Environment with the full .pc path incl. libdrm/libinput, `path = [ zig pkg-config ]` (68-85).
- `compositor-demo` service: manual (`systemctl start compositor-demo`), same shape, Environment WITHOUT libdrm/libinput .pc paths (89-105).

`scripts/vm-e2e.sh` — headless E2E, run by `compositor-demo`:
- `set -uo pipefail` (6), `exec > /dev/console 2>&1` (7).
- cd fail → poweroff (9); 9p remount `cache=none`, errors swallowed (12); share-sanity echo of `grep -c wantDrmBackend src/server/main.zig` (13).
- build: HOME/XDG_CACHE_HOME set (19-20), `zig build --prefix /tmp/zo --cache-dir /tmp/zc --global-cache-dir /tmp/zgc -Denable_raylib=false` (21-22); binary-exists check → poweroff on fail (23-29). NO cache clean.
- run: `WAYLAND_BACKEND=headless WAYLAND_SYNTH_INPUT=1 WAYLAND_LOG=err WAYLAND_RUN_FRAMES=400`, server stdout → /tmp/srv.out, **stderr dropped** (33-35); socket wait 40×0.5 s (38-42) → poweroff on timeout (44-47); client runs with no in-script timeout (49); kill server, verdict CLIENT-OK/rc, poweroff (51-58).

`scripts/vm-drm-e2e.sh` — DRM/KMS + libinput E2E, run by `compositor-demo-drm`:
- cd fail → poweroff (11); 9p remount (14); share-sanity echo (15); **forced clean build**: `rm -rf /tmp/zo /tmp/zc /tmp/zgc` (21), build (26-27), binary-exists → poweroff (28-34).
- binary wiring smoke: `grep -a -c "WAYLAND_BACKEND"` on the binary, 0 → diagnostics + poweroff (35-49).
- PRE-RUN kernel-log dump: `if ! grep -q VM-DRM-E2E-OK /tmp/srv.out` → `journalctl -k | grep -iE "virtio|drm|atomic|kms" | tail -40` (50-55) — runs before the server starts (62-65).
- run: `WAYLAND_BACKEND=drm WAYLAND_LIBINPUT=1 WAYLAND_SYNTH_INPUT=1 WAYLAND_LOG=err,server=debug,surface=debug,xdg=debug,shm=debug,drm=info,libinput=info WAYLAND_RUN_FRAMES=600`, stdout+stderr → /tmp/srv.out (62-65); socket wait 120×0.5 s (68-72) → poweroff (73-77); client → /tmp/cli.out (79-80); server self-stop wait 40×0.5 s then kill+wait (82-88).
- verdicts: `DRM_LINES=$(grep -c "drm:" srv.out)` (90); failure diagnostics incl. a `strings` invocation (92-106); `LIBINPUT_LINES=$(grep -c "libinput:" ...)` (107); gate = rc==0 AND CLIENT-OK in cli.out AND DRM_LINES>0 AND LIBINPUT_LINES>0 (109-110); leak check `grep -c leaked` printed but not gated (111-113); OK/FAIL echo, poweroff (113-121).

`scripts/uinput-devices.py` — virtual input tool (python-evdev):
- docstring 3-28 (usage: key/mousemove/click/scroll, "Run as root ... inside the VM"); `make_keyboard` (37-41), `make_mouse` absolute ABS_X/ABS_Y 0..0xFFFF + REL_WHEEL (44-52); `resolve_key` (63-66), `clamp` (68-72); `main` command loop with `finally` device close (74-135).

## Gaps

1. Headless E2E service cannot build against current build.zig. `compositor-demo`'s Environment omits libdrm.dev/libinput.dev from PKG_CONFIG_PATH (vm.nix:100) while build.zig runs `pkg-config --cflags libdrm` as a hard configure-time step (build.zig:76) and links `drm`/`libinput`/`udev` unconditionally (build.zig:84-91; only raylib is guarded, 153-174). The drm service's Environment has the full path (vm.nix:80). The author's own comment (vm.nix:78) says `environment.variables` does not reliably reach services, so the headless build fails → VM-E2E-FAILED every run. Severity: medium-high (headless regression gate is dead as configured; boot gate unaffected). Fix: add `${pkgs.libdrm.dev}/lib/pkgconfig:${pkgs.libinput.dev}/lib/pkgconfig` to vm.nix:100. [RESOLVED 2026-08-09 — empirically: with the paths added, the headless gate passes in the VM (`VM-E2E-OK`, CLIENT-CAPTURE pixels verified + CLIENT-OK, run via `systemctl start compositor-demo`); the fix was applied and verified. The vm.nix:100 Environment now matches the DRM service's.]

2. `vm-e2e.sh` has no forced clean build; stale binaries can mask a failed build. /tmp PERSISTS across VM runs: the qemu-vm tmpfs on /tmp is conditional on `boot.tmp.useTmpfs` (qemu-vm.nix:1449-1458), default off, so /tmp lives on the persistent ext4 root (diskSize, vm.nix:34). After a boot whose `zig build` failed (e.g. broken source in the shared tree), the previous boot's `/tmp/zo/bin/*` survives; the existence check (vm-e2e.sh:23) passes on the stale binary and the E2E runs an old build → false verdict. vm-drm-e2e.sh:21 does `rm -rf /tmp/zo /tmp/zc /tmp/zgc`; vm-e2e.sh does not. Severity: medium. Fix: same `rm -rf` in vm-e2e.sh (or compare binary mtime against build start).

3. Binary wiring check is a weak staleness smoke; its comment overstates it. `grep -a -c "WAYLAND_BACKEND"` (vm-drm-e2e.sh:37) matches a literal emitted by BOTH selector fns, `wantDrmBackend` (main.zig:1018) and `wantRaylibBackend` (main.zig:1024) — the raylib guard at main.zig:246 is a runtime `and`, so the fn (and its string) compiles in the `-Denable_raylib=false` guest build. The check therefore proves "backend env parsing compiles", not "drm wiring present": a source tree with the drm branch stubbed, or a stale 9p view differing in content, still yields WIRED ≥ 1. It only catches the specific case "stale source predates the WAYLAND_BACKEND env var entirely". Additionally `grep -c` counts LINES, and a binary is mostly one line, so WIRED is 1-3 regardless of occurrence count. Severity: low-medium (serves its intended stale-9p case, overclaimed as wiring proof). Fix: grep a drm-only .rodata string, e.g. `grep -a -c "drm: modeset ok"` (format string drm.zig:436 exists iff drm.zig compiles).

4. `drm_lines` counts error lines as pass evidence. The gate `[ "$DRM_LINES" -gt 0 ]` (vm-drm-e2e.sh:109) counts ANY line containing "drm:" — the drm backend's failure messages carry the same "drm: " prefix (drm.zig:182, 208, 217, 232, 249, 271, 282, 304, 313, 324, 337, 347, 360, 380, 386, 483). The socket timeout (73-77) catches hard init failure, but a soft runtime failure (e.g. "drm: page flip already pending", drm.zig:483) inflates DRM_LINES → the drm criterion passes while the backend is broken. Severity: low-medium. Fix: grep the success line `drm: modeset ok, output live` (drm.zig:436) instead of the bare tag.

5. The kernel-log dump is misplaced: it runs BEFORE the run it diagnoses. vm-drm-e2e.sh:52-55 executes before the server starts (62-65); /tmp/srv.out is truncated by the run (65), so at line 52 it holds only the PREVIOUS boot's content (persistent /tmp, Gap 2). First boot: block always fires (harmless journalctl+pipe cost every boot). Later boots: it reflects the previous run; the CURRENT run's DRM failure never gets a kernel dump — the failure branch (114-118) prints only srv.out/cli.out tails. The stated intent ("virtio-gpu logs atomic rejections to dmesg") is never served for the current run. Severity: low. Fix: move the `journalctl -k` block into the else branch at line 114.

6. Leak check is advisory, not a gate, with false-zero paths. LEAKS is computed and printed, then VM-DRM-E2E-OK is emitted unconditionally (vm-drm-e2e.sh:111-113); a nonzero count never fails the run despite "expect 0". False zero: the backstop `kill "$SRV"` (87) delivers SIGTERM; if the server has not yet self-stopped, the DebugAllocator deinit (main.zig:174) never runs and no "leaked" lines appear. Severity: low. Fix: add `[ "$LEAKS" -eq 0 ]` to the gate condition, or drop the check.

7. 9p staleness defense is incomplete: remount errors are swallowed, and `rm -rf` cannot fix a stale source view. `mount -o remount,cache=none ... 2>/dev/null || true` (vm-e2e.sh:12, vm-drm-e2e.sh:14) hides remount failure; the DRM script's own comment documents observed staleness across boots despite the remount (19-20). The 9p share mounts with kernel-default cache (the qemu-vm mount options list no cache for non-nix-store tags; cache= is added only for the nix-store tag, qemu-vm.nix:1425-1430). If the remount fails, cache=loose persists and the guest reads stale file content; `rm -rf /tmp/zc` (21) clears zig's build cache but not the 9p page cache, and zig's content-addressed cache happily reuses a stale view. Gap 3 is the only backstop and only catches total marker absence. Severity: medium. Fix: drop `|| true` and fail the script when the remount fails, or verify the active cache mode (`mount | grep -q 'cache=none'`) before building.

8. The host-side `timeout 480` wrapper contract is unversioned. The guest scripts power off on every path (vm-e2e.sh:9, 27, 45, 58; vm-drm-e2e.sh:11, 32, 47, 75, 121) and every in-guest wait is bounded: socket loops 20 s / 60 s (vm-e2e.sh:38-42, vm-drm-e2e.sh:68-72), server-exit loop 20 s (83-86), client waits self-bounded by `timeout_ms = 5000` per step (client.zig:31; CLIENT-TIMEOUT → rc≠0 → FAIL), server watchdog 5 s (main.zig:83, 449-453, 628-631), and `-no-reboot` (vm.nix:31) turns panic/reboot loops into qemu exit. The only external guard is the host `timeout 480` and its exit-124/OK-line semantics — no wrapper file exists in the repo (vm.nix:6 points at an ad-hoc `/tmp/wl-vm` flake). If the wrapper treats 124 as pass, a hung VM passes; if it greps the console for the OK line, kernel printk interleaving (drm.debug=0xf) is a (low-probability) flake source. Severity: medium (contract risk, not an observed bug). Fix: version a `scripts/run-vm-e2e.sh` wrapper (timeout, 124 → FAIL, exact OK-line match on the serial log).

9. RUN_FRAMES vs client-duration race. The server stops at WAYLAND_RUN_FRAMES regardless of client progress (main.zig:806-809; parse 368-373); the client must finish all steps (M3 input wait, screencopy, pixel verify, final roundtrip client.zig:228-282) before teardown. DRM: 600 frames ≈ 9.6 s at 16 ms (vm-drm-e2e.sh:64); headless: 400 ≈ 6.4 s (vm-e2e.sh:34). On a slow VM the client can exceed the budget → disconnect mid-run → flaky FAIL. No timing data in the repo. Severity: low (flakiness risk). Fix: stop the server when the client disconnects after CLIENT-OK, or have the client exit well before RUN_FRAMES.

10. Dead `strings` invocation in the failure diagnostics. vm-drm-e2e.sh:99 runs `strings /tmp/zo/bin/wayland-server | grep -c ...` while the script's own comment says the guest has no `strings` binary (36) — command-not-found (127), the diagnostic prints nothing; harmless (no `-e`) but dead and misleading. Fix: use `grep -a` as at line 37, or delete the line.

11. Share-sanity grep is informational only, and its label overclaims. `grep -c wantDrmBackend src/server/main.zig` (vm-e2e.sh:13, vm-drm-e2e.sh:15) currently yields 2 (fn def main.zig:1017, call main.zig:240 — verified). It does not gate: a renamed/removed marker prints "0 drm-wiring refs" and the run continues. The label "drm-wiring refs" overstates a marker count, and it checks only main.zig, not the drm backend module. Severity: low. Fix: either gate on it (`!= 2` → fail with diagnostics) or reword to "marker refs".

12. `drm.debug=0xf` (vm.nix:20): cost vs benefit. All DRM_UT categories (CORE|DRIVER|KMS|PRIME) print to the serial console + journal at boot and each modeset — bounded noise, small boot slowdown. Benefit: kernel-side atomic-rejection details for the journalctl dump — which currently never fires for the current run (Gap 5). Severity: none (acceptable). Recommendation: keep the param and fix Gap 5; trim to `0x2` (KMS) only if console noise matters.

13. `uinput-devices.py` is not part of the E2E gate. Verified: no reference in vm.nix/vm-e2e.sh/vm-drm-e2e.sh; guest input comes from virtio-keyboard/mouse through libinput plus WAYLAND_SYNTH_INPUT (vm.nix:27-30, scripts). The guest image ships no python3/evdev (vm.nix:45-60), so the tool cannot run in the guest as shipped — it is host-side interactive tooling, and its docstring ("Run as root ... inside the VM", line 9-10) is stale for that image. Severity: informational (no gate impact). Fix if in-VM injection is wanted: add python3 + python-evdev to systemPackages and wire a call site.

14. Headless script discards server stderr. `> /tmp/srv.out 2>/dev/null` (vm-e2e.sh:35) is correct for socket detection (the WAYLAND_SOCKET line goes to stdout, main.zig:397-401) but loses all server log output, so a headless failure needs a second run to diagnose. The DRM script captures both streams (vm-drm-e2e.sh:65). Severity: low. Fix: `2>&1` and keep WAYLAND_LOG=err.

## Verdict

Trustworthy as the DRM/libinput regression gate, with caveats. The boot gate (`compositor-demo-drm`) is structurally sound: every in-guest wait is bounded, every path reaches `poweroff -f`, `-no-reboot` contains panics, the build is force-cleaned, and the client is self-timebounded, so a hung or crashing run FAILs rather than stalls. The verdict greps are grounded: "drm:" and "libinput:" match only real backend log lines (drm.zig:436 etc.; main.zig:479), and "CLIENT-OK" is the client's explicit success verdict (client.zig:282). Caveats: (1) the drm criterion counts failure lines as pass evidence (Gap 4) — a soft-failing drm path can pass the drm criterion; (2) the leak check never fails the gate (Gap 6); (3) the 480 s wrapper contract is unversioned (Gap 8); (4) the pre-run dmesg dump never serves the run it diagnoses (Gap 5); (5) the headless unit is likely dead as configured (Gap 1) and lacks the clean build (Gap 2). Verdict: YES for "does drm+libinput init and can the client complete" — the gate's actual question; NO as proof of correct drm/libinput behavior under load, where Gaps 4 and 6 leave blind spots.
