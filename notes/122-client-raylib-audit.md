Scope: `src/server/client.zig` (the E2E test client, 656 lines), `src/server/raylib.zig` + `src/server/raylib_input.zig` (host-only raylib output/input path, compiled only with `-Denable_raylib`). All wlroots/smithay citations verified by reading the cited lines.

## Comparison

### Frame-callback wait (client.zig:203-217, 461-472)
- ours: the client requests `surface.frame()` in the same batch as attach/damage/commit (client.zig:203-207) and waits for `wl_callback.done` (client.zig:214-217; `onFrameDone` client.zig:461-472). Matches the per-commit callback contract.
- wlroots: callbacks accumulate on the surface's pending list at commit (types/wlr_compositor.c:121-124) and are moved to the current list (types/wlr_compositor.c:371-374); `wlr_surface_send_frame_done` sends done and destroys each callback (types/wlr_compositor.c:1131-1139).
- smithay: N/A (callback delivery is inside the surface state machine, not a client-facing check).
- verdict: same contract. One callback requested, one done awaited, then the callback object is left un-destroyed (process exit).

### Configure/ack handshake (client.zig:156-169, 440-448)
- ours: empty commit -> configure (serial S1) -> ack S1 before the buffer commit (client.zig:158-169). The server validates unknown and already-acked serials (src/shell/xdg.zig:237-250) and rejects a buffer commit before ack (src/shell/xdg.zig:826-828).
- wlroots: ack searches the sent-configure list; unknown serial -> `XDG_WM_BASE_ERROR_INVALID_SURFACE_STATE` (types/xdg_shell/wlr_xdg_surface.c:74-89). Buffer before ack -> `XDG_SURFACE_ERROR_UNCONFIGURED_BUFFER`.
- smithay: ack looks up `pending_configures` (src/wayland/shell/xdg/mod.rs:219-222); buffer before ack -> `UnconfiguredBuffer` (src/wayland/shell/xdg/mod.rs:1617-1620).
- verdict: same handshake, both error checks present on both sides. The client acks exactly the serial it received (client.zig:168-169), so it never triggers either error.

### Raylib output path vs headless output contract
- `RaylibBackend.create` (raylib.zig:85-149) mirrors `HeadlessBackend.create` (src/backend/headless.zig:39-63): single output, fixed mode, timer-paced frames started in `start` (raylib.zig:169-181 vs headless.zig:68-81). Same `testState`/`commit`/`destroy` output impl shape (raylib.zig:62-65 vs headless.zig:24-26).
- `frameCb` re-arms the timer unconditionally with fixed-period arithmetic (raylib.zig:193-205) — the same pattern as headless (`frameCb`, headless.zig:91-97) and the same divergence from wlroots' commit-gated pacing (flagged in notes/114 Gaps 2).
- commit differs by design: raylib uploads the framebuffer into a window texture (full or damage-box) and draws; headless only logs. The upload region logic (raylib.zig:278-307) is verified correct: bounding box clamped to the framebuffer, null -> full upload for whole/empty/off-screen/full-size damage, region bytes are tight rows for `UpdateTextureRec`.
- verdict: close for lifecycle and pacing; raylib adds window/texture/input on top of the identical headless skeleton.

### Input translation (raylib_input.zig:125-151)
- Key tables verified against evdev scancode+8 for every entry: letters (65..90 -> 38,56,54,40,26,41,42,43,31,44,45,46,58,57,32,33,24,27,39,28,30,55,25,53,29,52), digits, space 65, escape 9, enter 36, tab 23, backspace 22, delete 119, arrows 114/113/116/111, page up/down 112/117, home/end 110/115, caps/scroll/num 66/78/77, F1-F12 67-76,95,96, shifts/ctrl/alt/super 50,37,64,133,62,105,108,134. All correct.
- Pointer: window coords rounded to the output (raylib_input.zig:136-141). Valid because the window and the output are both fixed at the create-time mode (raylib.zig:115, main.zig:247-253); no resize path (see Gaps 5).
- smithay/wlroots: N/A (input backends have no client analog).
- verdict: table correct; coordinate mapping valid only while the window never resizes.

## Gaps

1. `RaylibBackend.create` failure path double-frees and dereferences `undefined`. `errdefer allocator.destroy(rl)` (raylib.zig:130) and `errdefer base.destroy()` (raylib.zig:144) are both live when `output.Output.create` fails (raylib.zig:147); `base.destroy()` runs the impl `destroy` (raylib.zig:184-191) which calls `rl.out.destroy()` on the unassigned `rl.out` (`undefined`, raylib.zig:35, assigned only at raylib.zig:148) and frees `rl`, then the errdefer frees `rl` again. Same pre-existing pattern in headless (src/backend/headless.zig:44, 49-50, 62). Severity: low — reachable only via OOM in `Output.create`, but it is UB, not a graceful error. The loaded texture also leaks on the alloc-failure paths (no `errdefer raylib.UnloadTexture` after raylib.zig:125).
2. `waitForEvent` aborts the whole run on poll EINTR. The poll error catch (client.zig:586-591) turns any signal (SIGCHLD/SIGWINCH/...) into CLIENT-ERROR + `return err` instead of re-polling. Severity: low — no signal handlers in the VM/scripted E2E, but poll semantics require a retry loop.
3. The client never acks the server's second configure. The server sends a second configure with the output size at first map (main.zig:911-930, "First map: give the toplevel its real size"); the client overwrites `configure_serial`/`got_configure` (client.zig:443-448) and the ack at client.zig:169 happens before the buffer commit, so configure #2 is never acked. Legal today (the client never commits again, and wlroots/smithay enforce ack-before-commit, not ack-every-configure — wlr_xdg_surface.c:74-89, smithay src/wayland/shell/xdg/mod.rs:219), but it is a latent protocol hazard: any future second commit without acking #2 would trip the server's own already-acked-serial logic (xdg.zig:237-250) or the wlroots-style unknown-serial error. The client also never inspects the configure size against its 1280x720 buffer.
4. Hardcoded 1280x720 couplings. The surface size, the output-mode assertion (client.zig:246-254) and the capture-size assertion (client.zig:534) all hardcode 1280x720; the DRM backend uses the connector's preferred mode (src/backend/drm.zig:530-602) and the VM forces `virtio-gpu-pci,xres=1280,yres=720` (scripts/vm.nix:28). Any other mode yields CLIENT-ERROR with pixel/size messages that do not say "mode mismatch". The second configure also always sends the 1280x720 constants (main.zig:927), matching the VM only.
5. Raylib commit has no size guard between the framebuffer and the fixed-size scratch. `bgraToRgba` (raylib.zig:308-318) copies `fb.w*fb.h` u32s into a scratch fixed at the create mode, with `@setRuntimeSafety(false)` (raylib.zig:309); a larger framebuffer writes past the scratch. Unreachable today: the raylib output mode is fixed at create (main.zig:247-253), the DRM-mode framebuffer resize (main.zig:490-502) never fires for raylib, and `WAYLAND_BACKEND=drm` and `=raylib` are mutually exclusive (main.zig:238-280). [INFERENCE] Latent hazard only.
6. Screencopy format/stride assumptions are correct but implicit. The client ignores the advertised `format` in the buffer event (client.zig:406-422) and hardcodes `.argb8888` (client.zig:417); the server always advertises ARGB8888 with a tight stride (src/screencopy.zig:197-198) and rejects non-ARGB8888 copy buffers (src/screencopy.zig:253-256). The copy is row-wise ARGB8888 into the client's memfd (src/screencopy.zig:278-292), so the pixel checks (client.zig:550-566: gradient B = `x*255/1280` with `(1000*255)/1280 = 199` integer division, cursor rect >= 200 at 53,53 inside the 8x8 rect at 50,50) are verified consistent with the server's fill and cursor. The XRGB8888 DRM scanout format (src/backend/drm.zig:331) never reaches screencopy, which copies the ARGB8888 pixman framebuffer. Self-consistent; fragile only if the server ever advertises another capture format.
7. Failed capture-buffer creation misreports as a timeout. `createBuffer` failure in the buffer handler is swallowed (`catch return`, client.zig:412-419); no copy is sent, the server sends no ready/failed, and `hasCaptureDone` (client.zig:491-494) times out -> CLIENT-TIMEOUT instead of CLIENT-ERROR. Cosmetic. The flush result there is also ignored (client.zig:421) unlike the checked flushes at client.zig:159, 208, 262.
8. Capture resources are never released on success. `setupCapture`'s errdefers (client.zig:500-515) cover failure; on success the second memfd/pool/buffer/mmap and the frame are never destroyed or unmapped, and the client sends no per-object destroy requests on any path (it relies on `wl.Display.disconnect`, client.zig:102). Invisible because the process exits; the server's disconnect teardown must (and does) handle abrupt closes, but the client never exercises destroy-request paths, so those server paths are not E2E-covered.
9. Docstring inaccuracy: the header says "wl_shm (v3)" (client.zig:6) but the client binds at the advertised version (client.zig:156 uses `g.version`; the internal server wl_shm global is version 2, src/buffers/shm.zig:3-6). Code is consistent; the comment is stale.
10. Raylib input is polled only inside commit. `PollInputEvents` + the hook run inside `commit` (raylib.zig:245-248); the unconditional timer re-arm (raylib.zig:193-205) keeps commits flowing at ~60fps so input is effectively polled per frame, but if pacing ever stops (timer error), input stops too, and a press+release between two polls is missed entirely (inherent to `IsKeyPressed` polling). Acceptable for a debug backend; the input path also has no resize tracking (window coords == output coords only while the window stays at the create-time size, raylib.zig:115).

## Verdict

The client is protocol-correct end to end: the configure/ack handshake matches the wlroots/smithay contract (verified against wlr_xdg_surface.c:74-89 and smithay xdg/mod.rs:219), the frame-callback wait matches `wlr_surface_send_frame_done` semantics (types/wlr_compositor.c:1131-1139), the memfd/pool sizing is exact (pool_size == stride*height, client.zig:29-30), the pixel verification math and the ARGB8888/stride assumptions match the server's screencopy path (src/screencopy.zig:197-198, 253-256, 278-292), and the synth-input expectations match the seat (enter+motion on first motion, seat.zig:177-200) and the server's synth (main.zig:656-674, cursor at 50,50, main.zig:1134-1136). waitForEvent race verdict: NO event-miss race — full `wl.Display.dispatch` reads all available data, the predicate is re-checked after every dispatch, poll precedes every wait, and spurious wakeups re-poll with a recomputed deadline; the 5s deadline fires at most one dispatch late. The real defects are all low severity: poll EINTR aborts the run (Gap 2), the raylib create OOM path double-frees (Gap 1), the unacked second configure is a latent hazard (Gap 3), and the 1280x720 hardcoding is a silent coupling to the VM resolution (Gap 4). The raylib backend is a faithful windowed clone of the headless output contract with correct pixel conversion and verified input tables; its fixed-size scratch (Gap 5) and window-locked coordinates (Gap 10) are safe only because the window and output never resize and the backend is mutually exclusive with DRM.
