## Gaps

1. **Three vendored protocols are inert.** `zwlr_layer_shell_v1`, `wp_viewporter`, `wp_fractional_scale_manager_v1` are codegen'd (build.zig) but no global is registered and no handler exists. Layer-shell blocks M4 (exclusive zones, panels/OSD); viewporter+fractional-scale block roadmap item 7 (sharp zoom) — note 103 already flags ours lacks VIEWPORT/OFFSET commit bits, so surface commit work is a precondition.
2. **No tablet input.** wlroots `tablet_v2/` and smithay `tablet_manager/` are full pen implementations (proximity, pressure, tilt, pads). For a canvas-first compositor this is the single most on-brand input protocol and it is entirely absent.
3. **No pointer-gestures / relative-pointer / pointer-constraints.** Pinch-zoom, smooth pan deltas, and pointer lock are the natural canvas interactions; all three are missing (canvas-compositing.md risk 6 lists relative-pointer scaling by 1/z as a known hazard to handle).
4. **No linux-dmabuf.** Only `wl_shm` buffers exist (109/111 notes: shm-only rendering). GPU clients are unusable until dmabuf import + feedback exists; this is a hard dependency of the gles2/EGL renderer milestone (M5).
5. **No xdg-output.** `wl_output` v4 exists but lacks logical position/size, so multi-monitor/video-wall clients cannot lay out across outputs (canvas-compositing.md §6).
6. **Selection surface is data-device-only.** gtk primary-selection (middle-click) and data-control (clipboard managers) are missing; the 108 note's seat_data core would carry both.
7. **No xdg-activation.** Without activation tokens, focus-stealing policy is impossible; standard desktop clients expect it.
8. **Capture is stuck at wlr-screencopy v1.** No ext-image-copy-capture (dmabuf capture, cursor sessions) — the direction both references moved to; smithay dropped wlr-screencopy entirely.
9. **No session-lock / security-context.** No way to lock the canvas or sandbox client contexts; matters for real deployment, not for the library milestones.
10. **smithay v0.7 dropped five wlr protocols** (gamma-control, output-management, output-power, virtual-pointer, wlr-screencopy — grep-verified). For those, wlroots is the only in-reference implementation; a zig port must read wlroots C alone.

## Verdict

Yes — the references have substantial shell-protocol breadth beyond xdg-shell, and a clear core of it is worth taking. The three vendored protocols come first: layer-shell (M4), viewporter and fractional-scale (roadmap item 7) are already in the build and are exactly what a zoomable canvas needs. Next tier for a canvas-first compositor: input-side protocols (tablet, relative-pointer, pointer-gestures, pointer-constraints) because pan/zoom/draw are the product; then selection (primary-selection, data-control, M8), linux-dmabuf (unblocks GPU clients), and xdg-output (multi-monitor correctness). Optional but cheap: cursor-shape, single-pixel-buffer, idle-inhibit/notify, virtual-keyboard, xdg-activation, xdg-decoration, foreign-toplevel (M8). Out of scope for this project: xwayland (a second compositor), drm-lease, transient-seat, color-management/representation, legacy server-decoration, superseded export-dmabuf, and the smithay-only frame-pacing protocols (commit-timing, fifo). smithay is the weaker reference here — it dropped five wlr protocols — so wlroots types/ is the primary porting source for the wlr-* family.
