# Compositor / Surface / Buffer — breadth vs wlroots 0.20.2 + smithay v0.7.0

Scope: our `src/compositor/{compositor,surface,region,role}.zig` + `src/buffers/{buffer,shm}.zig`
vs wlroots 0.20.2 (clone `~/projects/freedesktop-wlroots-wlroots`) and smithay v0.7.0
(clone `~/projects/github-Smithay-smithay`). Parity notes 102/103/104 covered per-function
parity; this note is the breadth inventory: whole features/protocols/backends in the
compositor/buffer area that we lack entirely. All paths relative to the clone roots and
verified by reading file lists/headers, not memory.

## Gaps

1. **Render ignores surface scale and transform.** The state machine snapshots both (surface.zig:118-121) and uses them only to translate damage (surface.zig:604-616); the canvas pass draws the texture 1:1 at buffer size (main.zig:1103-1104, compositeCanvas world_w/h = rect = buffer size). Surface-local size is never computed for rendering or input: at scale != 1 or non-normal transform the drawn size, hit region, and damage are all wrong. This is the largest gap — it blocks HiDPI clients outright and the canvas zoom plan (canvas-compositing.md §5) depends on correct scale application.
2. **No output enter/leave.** Clients cannot learn which outputs (and their scale/transform) a surface occupies, so they cannot pick a buffer scale; the events are protocol-visible and wlroots ships helpers (`wlr_compositor.c:1071-1128`). Nothing in src sends wl_surface.enter/leave (grep-verified).
3. **No viewporter.** Only generated bindings exist (root.zig:113); no global, no state, no `get_buffer_source_box`. canvas-compositing.md §5 names viewporter as the mechanism for sharp zoom; without it clients cannot crop/scale and the compositor has no surface-level viewport state.
4. **No DMA-BUF path end to end.** The `get_dmabuf` vtable slot exists but is always null; there is no linux-dmabuf-v1 global, no import, no feedback, and the attach path only resolves shm resources (`wire.shm.Buffer.get`, shm.zig:212-217). wlroots/smithay both have full protocol + feedback + import. Deferred by the pixman renderer, but the resource-registry seam (wlroots `resource.c:11-60`) is the missing plumbing that would let a future dmabuf backend join without touching the surface.
5. **No preferred buffer scale/transform hints.** Neither `set_preferred_buffer_scale/_transform` nor smithay's `send_surface_state` exists, so v6+ clients render at scale 1 by default — blurry under zoom until fractional-scale is added.
6. **No surface-tree traversal helpers.** wlroots' `get_root_surface`/`for_each_surface`/`surface_at`/`get_extents` and smithay's tree walkers are absent; the server does ad-hoc `surface_entries` iteration (main.zig:97-103). Fine today (one output, flat scene), but canvas hit testing through subsurfaces under a camera needs the tree abstraction.
7. **No cached state / commit blockers.** wlroots' `lock_pending`/`unlock_cached`/`synced` and smithay's transaction queue + `add_blocker` let protocol layers delay or reject commits (sync-subsurface state, dmabuf readiness, commit timing). Ours applies every commit directly. Not blocking today; becomes blocking when dmabuf readiness or commit_timing lands.

## Verdict

Yes — both references have substantial additional functionality in this area that we lack entirely, and the worth-taking subset for a canvas-first compositor is clear: (1) applying the snapshot scale/transform at render (with surface-local size feeding both draw and pick) is mandatory and currently wrong; (2) output enter/leave, (3) viewporter, and (4) preferred-scale hints are the protocol layer of the canvas zoom plan — canvas-compositing.md §5 explicitly needs viewporter and fractional-scale-style hints, and enter/leave is the scale-selection signal clients rely on; (5) the wlr_buffer resource registry (wlroots `resource.c`) is cheap plumbing that makes the Buffer vtable's `get_dmabuf` slot real. Everything GPU-flavored (linux-dmabuf-v1 + feedback, wlr_dmabuf_buffer, export-dmabuf, wl_drm legacy) is out-of-scope while the renderer is pixman and should be deferred, not built on the wrong backend; wlr_client_buffer texture caching, per-buffer damage aging, and commit blockers are optional refinements to pick up when the GPU path or partial-upload rendering lands. The one feature where we lead both references (get_release, v7) should stay.
